# DevProfile

Личный сайт-профиль в стиле Steam-сообщества: dev-статистика (GitHub/Steam) + фитнес-трекер с реальными аккаунтами, регистрацией и БД.

## Идея проекта

DevProfile — единый цифровой профиль человека, оформленный в узнаваемом визуальном языке Steam-сообщества: уровень, опыт, значки, лента активности, статистика. Вместо игровой активности профиль отражает реальные стороны жизни владельца и со временем должен закрывать несколько задач в одном месте:

- **Профиль разработчика** — живая статистика по GitHub (репозитории, языки, активность) и Steam, оформленная как достижения и уровень, а не сухие цифры.
- **Фитнес-трекер** — параметры тела, результаты InBody, дневник тренировок, таймер отдыха, достижения и рейтинг по возрастным группам, чтобы прогресс был измерим и мотивировал так же, как игровой опыт.
- **Личный кабинет** — полноценный аккаунт с регистрацией, настройками профиля (аватар, био, фон, связанные сервисы) и хранением данных на сервере, а не только на одном устройстве.
- **Витрина интересов** (задел на будущее) — хобби, друзья, чаты, любимые фильмы и игры с достижениями в них; места под эти разделы уже зарезервированы в интерфейсе.

Итоговая цель — не набор разрозненных трекеров и профилей в разных сервисах, а один персональный сайт, который одинаково хорошо показывает «чем я занимаюсь как разработчик», «как я слежу за собой физически» и, в перспективе, «кто я вне работы» — с игровой подачей (уровни, значки, рейтинг), которая делает регулярную активность нагляднее и приятнее.

**Текущая версия: v0.2.0 «Фитнес-трекер и личный кабинет»** (2026-08-28)

## Журнал изменений

### v0.2.0 «Фитнес-трекер и личный кабинет» — 2026-08-28

Профиль в стиле Steam-сообщества дополнен фитнес-трекером и реальными аккаунтами: раньше сайт работал с единственным захардкоженным демо-профилем и жил только на клиенте, теперь это многопользовательский сервис с собственным бэкендом и базой данных.

**Добавлено**
- Вкладка **Fitness** рядом с Dev-вкладкой: параметры тела, история замеров, InBody-сканы, дневник тренировок, рабочий таймер отдыха между подходами, достижения, рейтинг по возрастным группам.
- Отдельный бэкенд (`Сервер\`) на Express + TypeScript + Prisma + PostgreSQL с JWT-авторизацией и хешированием паролей (bcrypt).
- Регистрация и вход — вместо единственного демо-профиля у каждого пользователя теперь свой аккаунт.
- Общий каталог упражнений и сид с ботами-конкурентами для рейтинга — таблица лидеров содержательна сразу после установки, а не пустует до появления реальных пользователей.
- Формы добавления замеров, InBody-сканов и тренировок — данные пишутся в базу и сохраняются между сессиями.
- Панель **«Настройки»**: аватар, личная информация (имя/локация/био), связанные аккаунты (GitHub/Steam), фон профиля, смена пароля (старый пароль + новый + подтверждение).
- Эндпоинты обновления профиля и смены пароля на сервере.
- Автоматическое обновление данных аккаунта при каждой загрузке страницы — сохранённая на клиенте сессия всегда синхронизирована с сервером.

**Изменено**
- Профиль больше не привязан к единственному захардкоженному пользователю — имя, аватар, био, ссылки на GitHub/Steam и фон берутся из аккаунта, под которым выполнен вход.
- Хранение фитнес-данных (тренировки, замеры, InBody, упражнения, рейтинг) перенесено с клиента на сервер; на клиенте остаются только вычисляемые значения — бейджи и уровень.
- Настройка CORS сделана гибкой по портам локального окружения — фиксированный порт мешал параллельной разработке.
- Расчёт места в рейтинге и бейджа за топ-3 разделён на два прохода на сервере, чтобы устранить циклическую зависимость (бейдж зависел от места, место — от количества бейджей).

**Удалено**
- Тестовые фитнес-данные — заменены реальными, приходящими из базы данных.
- Отдельный редактор фона — объединён с общей панелью настроек.
- Неиспользуемые параметр и кнопка в компоновке страницы, оставшиеся от более ранней версии интерфейса.
- Резервное значение Steam ID из переменных окружения по умолчанию — в многопользовательском режиме показ чужого личного профиля новым аккаунтам был ошибкой поведения, а не удобством.

**Исправлено**
- Всплывающие подсказки у достижений обрезались в узких колонках интерфейса — вынесены за пределы контейнеров с позицией, привязанной к экрану, а не к родителю.
- Контент страницы не центрировался на широких экранах — конфликт пользовательских стилей сброса с системой CSS-слоёв применяемого CSS-фреймворка.
- Локальный сервер разработки был доступен только по IPv6 на части окружений, из-за чего `localhost` не открывался — явно задан IPv4-адрес.
- Бесконечный цикл перерисовки интерфейса, вызванный нестабильной ссылкой на пустой массив по умолчанию в хуках загрузки данных.
- Сообщение об ошибке при регистрации не отличало сетевые сбои от неверных данных — теперь показывается фактическая причина ошибки.
- Кнопка «назад» в браузере при открытой панели настроек закрывала не только панель, но и уводила с сайта целиком — теперь корректно закрывает только панель, оставаясь на странице.
- Аварийное завершение работы приложения для ранее сохранённых сессий, в которых отсутствовали новые поля профиля, — добавлены значения по умолчанию.

### v0.1.0 «Dev-профиль» — 2026-06-23 – 2026-07-12

Исходная версия: профиль в стиле Steam-сообщества с живой GitHub/Steam-статистикой, бейджами, активностью, настраиваемым фоном — без бэкенда, все данные через публичные API GitHub/Steam и локальный демо-профиль.

## Установка и запуск локально

### 1. Требования
- Node.js 20+
- PostgreSQL 17 (локально)

### 2. PostgreSQL

Если ещё не установлен — в **elevated PowerShell** (правой кнопкой → «Запуск от имени администратора»):

```powershell
winget install --id PostgreSQL.PostgreSQL.17 --source winget
```

Установщик попросит задать пароль для пользователя `postgres` — он понадобится в `DATABASE_URL` на следующем шаге.

### 3. Сервер (`Сервер\`)

```bash
cd Сервер
npm install

# Скопировать .env.example → .env и заполнить:
#   DATABASE_URL — с паролем, который задан при установке PostgreSQL
#   JWT_SECRET   — любая длинная случайная строка
cp .env.example .env

# Применить миграции и создать БД (если её ещё нет) — заодно
# автоматически прогонит сид (15 упражнений + боты для лидерборда)
npx prisma migrate dev

# Запуск в dev-режиме (порт 4000, с автоперезапуском)
npm run dev
```

Проверить, что сервер жив: `curl http://127.0.0.1:4000/api/health` → `{"ok":true}`.

Другие полезные команды:
```bash
npm run db:seed      # прогнать сид повторно (безопасно, идемпотентно)
npm run build        # собрать в dist/
npm start             # запустить собранную версию
```

### 4. Клиент (`devprofile\`)

```bash
cd devprofile
npm install

# В .env должны быть (создать при отсутствии):
#   VITE_API_BASE_URL=http://127.0.0.1:4000/api
#   VITE_GITHUB_TOKEN=...      — свой GitHub personal access token (для Dev-вкладки)
#   VITE_STEAM_API_KEY=...     — свой Steam Web API ключ (для Dev-вкладки)

npm run dev
```

Откроется на `http://127.0.0.1:5173` (или следующем свободном порту, если 5173 занят).

### 5. Проверка

1. Открыть клиент в браузере → страница входа/регистрации.
2. Зарегистрировать аккаунт.
3. На вкладке **Fitness** добавить замер/тренировку — должны сохраниться и остаться после обновления страницы (F5).
4. В **Настройках** — указать GitHub/Steam, поменять пароль.
