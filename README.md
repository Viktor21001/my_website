# DevProfile

Личный сайт-профиль в стиле Steam-сообщества: dev-статистика (GitHub/Steam) + фитнес-трекер с реальными аккаунтами, регистрацией и БД.

## Идея проекта

DevProfile — единый цифровой профиль человека, оформленный в узнаваемом визуальном языке Steam-сообщества: уровень, опыт, значки, лента активности, статистика. Вместо игровой активности профиль отражает реальные стороны жизни владельца и со временем должен закрывать несколько задач в одном месте:

- **Профиль разработчика** — живая статистика по GitHub (репозитории, языки, активность) и Steam, оформленная как достижения и уровень, а не сухие цифры.
- **Фитнес-трекер** — параметры тела, результаты InBody, дневник тренировок, таймер отдыха, достижения и рейтинг по возрастным группам, чтобы прогресс был измерим и мотивировал так же, как игровой опыт.
- **Личный кабинет** — полноценный аккаунт с регистрацией, настройками профиля (аватар, био, фон, связанные сервисы) и хранением данных на сервере, а не только на одном устройстве.
- **Витрина интересов** (задел на будущее) — хобби, друзья, чаты, любимые фильмы и игры с достижениями в них; места под эти разделы уже зарезервированы в интерфейсе.

Итоговая цель — не набор разрозненных трекеров и профилей в разных сервисах, а один персональный сайт, который одинаково хорошо показывает «чем я занимаюсь как разработчик», «как я слежу за собой физически» и, в перспективе, «кто я вне работы» — с игровой подачей (уровни, значки, рейтинг), которая делает регулярную активность нагляднее и приятнее.

**Текущая версия: v0.6.0 «Админ-панель и роли»** (2026-08-31)

## Администрирование

Три роли: **Пользователь** → **Администратор** → **Создатель**. Ровно один Создатель — владелец сервиса; эта роль назначается один раз напрямую в базе и не выдаётся через интерфейс. Кнопка «🛡 Админ-панель» в шапке видна только Администраторам и Создателю.

**Иерархия и её защита** (проверяется на сервере при каждом запросе, а не только в интерфейсе):
- Создателя нельзя забанить, удалить, сбросить ему пароль или лишить его роли — никому и никогда, в том числе ему самому через админ-панель.
- Права Администратора выдаёт и забирает только Создатель. Сам Администратор не может назначить или разжаловать другого Администратора.
- Обычный Администратор может банить, разбанивать, удалять и сбрасывать пароль только обычным Пользователям. Те же действия над другим Администратором доступны только Создателю — Администраторы не могут модерировать друг друга.
- Никто не может применить эти действия к самому себе через админ-панель.

**Бан** — временный (администратор указывает число дней) или постоянный, причина обязательна. Забаненный не может войти, а если он уже был залогинен — теряет доступ на первом же следующем запросе к серверу, без ожидания истечения токена. Временный бан снимается сам по истечении срока, без ручного разбана.

**Сброс пароля** — сервер генерирует случайный временный пароль и показывает его администратору один раз во всплывающем блоке; нигде не сохраняется и не логируется в открытом виде — администратор сообщает его пользователю лично.

**Журнал действий** — каждое действие любого администратора (бан/разбан/удаление/сброс пароля/выдача или отзыв прав) записывается: кто, что, над кем, когда, с деталями. Виден только Создателю, во вкладке «Журнал действий» админ-панели.

## Журнал изменений

### v0.6.0 «Админ-панель и роли» — 2026-08-31

Инструмент модерации: роли пользователей (Пользователь/Администратор/Создатель), бан, удаление аккаунтов, сброс пароля и журнал действий всех администраторов. Подробные правила — в разделе «Администрирование» выше.

**Добавлено**
- Роли **Пользователь / Администратор / Создатель** — ровно один Создатель (владелец сервиса), права Администратора выдаёт и отзывает только он.
- Кнопка «🛡 Админ-панель» в шапке — видна Администраторам и Создателю.
- Список всех пользователей в админ-панели: аватар, имя, логин, почта, id, роль, статус бана — с поиском по имени/логину/почте и подгрузкой следующих страниц по кнопке «Показать ещё».
- Бан пользователя — временный (с указанием числа дней) или постоянный, с обязательной причиной; разбан снимает его вручную, временный снимается сам по истечении срока.
- Сброс пароля пользователю прямо из админ-панели — сервер генерирует случайный временный пароль и показывает его администратору один раз.
- Удаление аккаунта пользователя администратором — с двойным подтверждением кнопкой (повторный клик в течение нескольких секунд).
- Выдача и отзыв прав Администратора — доступны только Создателю.
- Журнал действий администраторов (кто/что/над кем/когда, включая причину бана и т.п.) — отдельная вкладка админ-панели, видна только Создателю.

**Исправлено**
- Кнопка «Разбанить» не обновляла статус пользователя в списке сразу после нажатия — приходилось переоткрывать панель или обновлять страницу, чтобы увидеть, что бан снят. Теперь список пользователей обновляется сам сразу после любого действия (бан, разбан, удаление, выдача/отзыв прав).

### v0.5.0 «Перетаскивание панелей и вкладка General» — 2026-08-30 – 2026-08-31

Панели на вкладках Dev/Fitness/Games теперь можно перетаскивать и переставлять — порядок сохраняется на сервере. Поверх этого — четвёртая вкладка **General**, личная сводная страница, куда можно перетащить любую панель с любой другой вкладки: при наведении на кнопку General (или любой другой вкладки) во время перетаскивания та сама переключается, не прерывая жест.

**Добавлено**
- Перетаскивание панелей за ручку (☰, правый край шапки панели) на вкладках Dev/Fitness/Games — можно менять порядок внутри колонки и переносить панель между левой и правой колонкой; расположение сохраняется на сервере и восстанавливается при следующей загрузке.
- Новая вкладка **General** (первая, перед Dev) — личная сводная страница: общий ряд всех значков (GitHub и Steam вместе, без разделения по вкладкам), ряд фитнес-достижений и карточка «Обзор» с Dev- и Fitness-уровнем и прогрессом опыта рядом. Изначально почти пустая — наполняется перетаскиванием панелей с других вкладок, чтобы не превращаться в свалку дублирующихся виджетов.
- Перетаскивание панели между вкладками — при зажатии ручки и наведении на кнопку любой вкладки в шапке (включая General) та вкладка сама переключается, панель можно сразу отпустить в нужном месте уже на открывшейся вкладке.
- Вкладка по умолчанию при входе — выбирается в Настройках (General/Dev/Fitness/Games). У новых аккаунтов после регистрации по умолчанию открывается General; у уже существующих аккаунтов ничего не меняется (по-прежнему Dev), пока пользователь сам не выберет другую.

### v0.4.0 «Games, достижения и общая библиотека» — 2026-08-30

Третья верхнеуровневая вкладка **Games** забрала с Dev-вкладки всё, что связано с играми, и получила два новых блока — визуальную библиотеку Steam и агрегированные достижения по всей библиотеке. Библиотека упражнений на вкладке Fitness доросла до полноценной системы с правами доступа: своя библиотека, общая «Сообщество» и неизменяемый системный каталог. Плюс — часы в шапке, выбор локации/часового пояса и опциональные поля состава тела в замерах.

**Добавлено**
- Часы в StatusBar (по центру, между статусом и кнопками «Настройки»/«Выйти») — дата и время обновляются раз в секунду и подстраиваются под часовой пояс, выбранный в настройках, а не под часовой пояс браузера.
- Выбор часового пояса в Настройках — список из полутора десятков распространённых поясов (от Калининграда до Камчатки, плюс несколько зарубежных) с человекочитаемыми подписями; значения — настоящие IANA-идентификаторы, сервер валидирует присланное значение через `Intl.supportedValuesOf('timeZone')`.
- Выбор локации в Настройках — список городов вместо свободного текста; если нужного города нет, в конце списка пункт «Другое», открывающий обычное текстовое поле.
- Опциональные поля «% жира» и «Мышечная масса» в форме добавления замера тела — заполняются только при наличии анализатора состава тела. Отображаются на графике замеров (своя линия на каждый показатель, точки только там, где значение реально указано) и на силуэте тела.
- Библиотека упражнений на вкладке Fitness переведена на три вкладки: **Системная** (сид, никто не может изменить или удалить), **Моя библиотека** (создание своих упражнений, переименование библиотеки, редактирование и удаление своих упражнений) и **Сообщество** (упражнения всех остальных пользователей, доступны на чтение всем). Удалить чужое упражнение нельзя — можно только скопировать его себе, а форма копии требует изменить хотя бы одно поле, чтобы точная копия не сохранялась и не плодила дубликаты. Удаление упражнения, уже использованного в чьей-то тренировке, теперь блокируется понятной ошибкой вместо падения запроса по внешнему ключу.
- Новая вкладка **Games** (третья, после Dev и Fitness) — сюда перенесено всё игровое: плашка Steam-профиля, «Любимые игры», игровые бейджи (Геймер/Хардкор) и «Недавняя активность» (раньше по ошибке жила на вкладке Fitness).
- Блок **«Библиотека игр»** на вкладке Games — вся Steam-библиотека постерами (обложки `library_600x900` напрямую с CDN Steam), по 6 в строке, видно две строки, остальное скроллится колёсиком мыши; при наведении постер увеличивается, подсвечивается и снизу всплывает название игры с наработанным временем.
- Блок **«Достижения»** на вкладке Games — все полученные достижения по всей библиотеке квадратиками, как в самом Steam-клиенте. Без личного Steam API ключа блок притушен, с пояснением и подсказкой «?», как этот ключ получить (steamcommunity.com/dev/apikey). После того как ключ добавлен, кнопка «Синхронизировать» запускает сбор достижений по всем сыгранным играм в фоне на сервере — полоса прогресса с процентом и счётчиком «N из M игр» обновляется, пока идёт синхронизация. При наведении на достижение оно увеличивается и показывает название, игру, описание, дату получения и процент игроков Steam, у которых оно тоже есть.
- Поле личного Steam API ключа в Настройках (отдельно от общего ключа сайта) — маскированный ввод, подсказка «?» с инструкцией по получению ключа, кнопка удаления сохранённого ключа.

**Изменено**
- Значки на Dev-вкладке (блок «Значки») теперь показывают только GitHub-бейджи — игровые (Геймер/Хардкор) переехали в свой собственный ряд значков на вкладке Games.
- Подсписок «Игры» внутри блока «Активность» на Dev-вкладке убран — тот же список недавно сыгранных игр теперь живёт на вкладке Games как часть блока «Недавняя активность», вместе с прогрессом по достижениям.
- Синхронизация достижений переведена с одного долгого блокирующего запроса (клиент ждал завершения всей синхронизации, вкладка выглядела зависшей на десятки секунд — минуты) на фоновую задачу на сервере: запрос на синхронизацию отвечает сразу же, а прогресс читается отдельным лёгким поллингом раз в 1.2 секунды.

**Удалено**
- Отдельный список «Игры» и карточка под него внутри блока «Активность» — заменены панелями на новой вкладке Games.

**Исправлено**
- Первое открытие вкладки Games ощутимо подвисало на аккаунтах с большой прожитой Steam-библиотекой — блок «Достижения» рендерил разом каждое полученное достижение по всей библиотеке (у активных аккаунтов — тысячи штук), и каждое тянуло за собой свою логику всплывающей подсказки. Теперь за один раз рендерится не больше 200 достижений, остальные — по кнопке «Показать ещё».
- Постеры в «Библиотеке игр» — тайлы фиксированной ширины не делят ширину панели без остатка, из-за чего отступ справа получался заметно больше отступа слева; сетка теперь центрируется по горизонтали, и оба отступа равны.
- Удаление личного Steam API ключа в Настройках теперь очищает и закэшированные в базе достижения — без ключа обновить их всё равно нельзя, а показывать молча устаревшие данные неверно.

### v0.3.0 «Реальные данные Steam» — 2026-08-29

Steam-интеграция на Dev-вкладке переведена с автоматического набора «топ-4 по времени» на реальный выбор пользователя и настоящие данные из Steam Web API: достижения, полная библиотека, желаемое, рабочие обложки игр.

**Добавлено**
- Привязка Steam-аккаунта в настройках теперь принимает логин или ссылку на профиль, а не только числовой SteamID64 — введённое значение резолвится в SteamID64 через Steam Web API перед сохранением.
- Блок «Недавняя активность» на вкладке Fitness — недавно сыгранные игры с обложкой, наработанным временем, датой последнего запуска и прогрессом по достижениям (счётчик, полоса прогресса, иконки последних полученных достижений). У Steam нет единого метода «достижения по всем играм сразу» и «иконки достижений по игроку», поэтому на каждую игру уходит два запроса — какие достижения получены и как выглядят их иконки — и результаты сводятся вместе.
- Панель выбора любимых игр (кнопка-глазик в шапке блока «Любимые игры»): поиск по всей библиотеке, ручной выбор до 7 игр с иконками и наработанным временем, счётчик «Выбрано: N / 7». После выбора семи игр остальные строки в списке блокируются, пока не убрать одну из уже выбранных.
- Панель «Любимые игры» на Dev-вкладке расширяется под фактическое количество выбранных игр (1–7) вместо жёстко зафиксированных четырёх.
- Счётчик игр в списке желаемого (Wishlist) в плашке Steam, рядом со счётчиком библиотеки.
- Иконка-подсказка у поля Steam в настройках профиля — при наведении показывает, где посмотреть логин (Steam → «Мой кошелёк» → строка «Пополнить баланс кошелька "логин"») и как получить SteamID64 (steamdb.com/ru/tools/steam-id-finder).
- График изменений замеров тела на вкладке Fitness (под-вкладка «Замеры») — отдельная цветная линия на каждый параметр (вес, грудь, талия, бёдра, бицепс, бедро) с точками по реальным датам замеров, общей осью слева с шагом в 10 единиц и фоновой сеткой, легендой текущих значений под графиком. Подписи дат снизу подстраиваются под фактическое число замеров — равномерно до 6 штук вместо только первой и последней, чтобы не перегружать ось при большой истории. Высота графика подогнана под соседнюю панель силуэта, чтобы блоки стояли вровень.
- Динамический силуэт тела рядом с графиком замеров — контур, отрисованный по детальной анатомической иллюстрации (векторизованный SVG на ~3300 точек контура), который меняется в реальном времени под фактические замеры: каждая точка масштабируется по X от анатомической оси (централь тела для торса и ноги, плечевая ось для руки) с плавной интерполяцией между опорными высотами (грудь/талия/бёдра/бедро/бицепс), плюс подписи-выноски, указывающие на настоящий видимый изгиб контура, а не на условную высоту.
- «+ Добавить тренировку» на вкладке Fitness → Тренировки — по умолчанию полностью ручной ввод (название, место, длительность, список подходов из открывающегося списка упражнений); ничего не подбирается само. Ниже — отдельная плашка «Сгенерировать тренировку»: раскрывает Тип тренировки (похудение / похудение с рельефом / массонабор / силовая) и Уровень подготовки, и только по явному нажатию «Сгенерировать» одним разом заполняет список подходов. Каталог упражнений расширен почти вдвое (до 28, плюс пользователь может дополнять его своими упражнениями — см. ниже) и размечен тегами «выполнимо дома», «базовое многосуставное» и «минимальный уровень подготовки» — по ним подбираются упражнения.
- Вес в строке подхода подставляется автоматически: для упражнений с собственным весом (без инвентаря) — вес тела из последнего замера на вкладке «Замеры» (не редактируется руками), для упражнений со штангой/гантелями/на тренажёре — вес последнего использования этого же упражнения в прошлых тренировках (можно поменять). Для упражнений на выносливость (планка, бег, велотренажёр, эллипсоид, скакалка) то же поле показывает не повторы, а время в минутах, пропорциональное выбранной длительности тренировки.
- Кнопка «Утвердить тренировку» сохраняет тренировку и сразу открывает живой проигрыватель: по очереди проводит по каждому подходу — для упражнений с инвентарём сначала просит ввести и подтвердить рабочий вес, затем обратный отсчёт для упражнений на время, пауза между подходами (по профилю выбранной цели) и короткая 8-секундная подготовка перед следующим упражнением; тренировку можно поставить на паузу или прервать в любой момент. Кнопка «Повторить» на карточках истории запускает тот же путь для уже выполненной тренировки — пересохраняет её подходы с сегодняшней датой (вес для упражнений со своим весом берётся заново из последнего замера) и сразу открывает проигрыватель.
- Плавание переработано в отдельную изолированную запись (свой тумблер «Плавание», не смешивается ни с генерацией, ни с весом/повторами, ни с проигрывателем): длина бассейна и один или несколько стилей (кроль/брасс/на спине/баттерфляй) с количеством проплытых бассейнов на каждый.
- Список истории тренировок ограничен пятью карточками по высоте — при большем числе тренировок появляется прокрутка внутри блока вместо бесконечного роста панели.
- Библиотека упражнений — пользователь может добавить своё упражнение (название, группа мышц, инвентарь, «можно дома», «на время»). Собственный вес против вводимого определяется прямо по полю «Инвентарь» — пусто, значит вес тела и не редактируется, указан — значит вес вводится и корректируется в тренировках; отдельного тумблера для этого нет, чтобы значения не расходились с тем, что реально ввёл пользователь.
- Секундомер вместо таймера отдыха на вкладке Fitness (правая колонка, под достижениями): круглый циферблат с цифровым временем в центре и двумя стрелками — одна отсчитывает общее время, другая время текущего круга. Старт → Круг/Стоп, Стоп → Сбросить/Продолжить; история кругов (номер, время круга, общее время) видна во время работы и на паузе, очищается только по «Сбросить секундомер».
- Календарь контрибуций GitHub (те же зелёные квадраты, что на github.com) и блок Activity overview с ромбовидным графиком долей коммитов/issues/PR/ревью и списком «Contributed to» — во вкладке Активность → GitHub. REST API GitHub такие данные не отдаёт, поэтому используется GraphQL-запрос (`contributionsCollection`) тем же токеном, что и остальная GitHub-интеграция.

**Изменено**
- Счётчик «игр в библиотеке» в плашке Steam берётся из полного списка игр аккаунта, а не из топ-4 «любимых» — раньше при библиотеке больше 4 игр показывалось заниженное число.
- Подсчёт очков за бейджи «Геймер» и «Хардкор» ведётся по всей библиотеке, а не по 4 играм с наибольшим временем — раньше суммарное время занижалось для аккаунтов с библиотекой больше 4 игр.
- Список любимых игр — раньше это был автоматический топ-4 по наработанному времени без возможности его изменить; теперь это осознанный выбор пользователя, сохраняемый на сервере, а прежнее поведение (топ-4 по времени) осталось как запасной вариант для аккаунтов, которые ничего не выбирали.
- Обложки игр (в «Любимых играх», пикере выбора и списке активности) строятся по appid напрямую через CDN Steam, а не по полю из ответа API, которое Steam давно перестал возвращать, — раньше из-за этого обложки не загружались вообще.
- Дата последнего запуска игры в «Недавней активности» берётся из полной библиотеки аккаунта — эндпоинт недавно сыгранных игр эту дату вообще не отдаёт.

**Удалено**
- Жёсткое ограничение списка любимых игр четырьмя позициями — заменено пользовательским выбором с лимитом в 7.

**Исправлено**
- Возрастные группы фитнес-рейтинга пересекались по граничным значениям (16-20, 20-25, 25-30, ...) — например, 20 лет одновременно попадало и в «16-20», и в «20-25», из-за чего было не очевидно, какую группу выбирать при регистрации. Диапазоны сделаны непрерывными и не пересекающимися: 16-20, 21-25, 26-30, 31-35, 36-40, 41+. На сервере значения в базе переименованы налету (без потери данных существующих аккаунтов).
- История тренировок сортировалась только по дате замера — у нескольких тренировок за один день дата совпадала вплоть до полуночи UTC, поэтому порядок среди них был произвольным, и только что добавленная тренировка не обязательно оказывалась наверху. Добавлено отдельное поле времени создания записи, история сортируется по дате, а при совпадении — по нему; у существующих тренировок, попавших под миграцию одним и тем же моментом бэкафилла, время создания восстановлено по порядку id (он у Prisma генерируется хронологически).

### v0.2.0 «Фитнес-трекер и личный кабинет» — 2026-08-28

Профиль в стиле Steam-сообщества дополнен фитнес-трекером и реальными аккаунтами: раньше сайт работал с единственным захардкоженным демо-профилем и жил только на клиенте, теперь это многопользовательский сервис с собственным бэкендом и базой данных.

**Добавлено**
- Вкладка **Fitness** рядом с Dev-вкладкой: параметры тела, история замеров, InBody-сканы, дневник тренировок, рабочий таймер отдыха между подходами, достижения, рейтинг по возрастным группам.
- Отдельный бэкенд (`Сервер\`) на Express + TypeScript + Prisma + PostgreSQL с JWT-авторизацией и хешированием паролей (bcrypt).
- Регистрация и вход — вместо единственного демо-профиля у каждого пользователя теперь свой аккаунт.
- Общий каталог упражнений и сид с ботами-конкурентами для рейтинга — таблица лидеров содержательна сразу после установки, а не пустует до появления реальных пользователей.
- Формы добавления замеров, InBody-сканов и тренировок — данные пишутся в базу и сохраняются между сессиями.
- Панель **«Настройки»**: аватар, личная информация (имя/локация/био), связанные аккаунты (GitHub/Steam), фон профиля, смена пароля (старый пароль + новый + подтверждение).
- Эндпоинты обновления профиля и смены пароля на сервере.
- Автоматическое обновление данных аккаунта при каждой загрузке страницы — сохранённая на клиенте сессия всегда синхронизирована с сервером.

**Изменено**
- Профиль больше не привязан к единственному захардкоженному пользователю — имя, аватар, био, ссылки на GitHub/Steam и фон берутся из аккаунта, под которым выполнен вход.
- Хранение фитнес-данных (тренировки, замеры, InBody, упражнения, рейтинг) перенесено с клиента на сервер; на клиенте остаются только вычисляемые значения — бейджи и уровень.
- Настройка CORS сделана гибкой по портам локального окружения — фиксированный порт мешал параллельной разработке.
- Расчёт места в рейтинге и бейджа за топ-3 разделён на два прохода на сервере, чтобы устранить циклическую зависимость (бейдж зависел от места, место — от количества бейджей).

**Удалено**
- Тестовые фитнес-данные — заменены реальными, приходящими из базы данных.
- Отдельный редактор фона — объединён с общей панелью настроек.
- Неиспользуемые параметр и кнопка в компоновке страницы, оставшиеся от более ранней версии интерфейса.
- Резервное значение Steam ID из переменных окружения по умолчанию — в многопользовательском режиме показ чужого личного профиля новым аккаунтам был ошибкой поведения, а не удобством.

**Исправлено**
- Всплывающие подсказки у достижений обрезались в узких колонках интерфейса — вынесены за пределы контейнеров с позицией, привязанной к экрану, а не к родителю.
- Контент страницы не центрировался на широких экранах — конфликт пользовательских стилей сброса с системой CSS-слоёв применяемого CSS-фреймворка.
- Локальный сервер разработки был доступен только по IPv6 на части окружений, из-за чего `localhost` не открывался — явно задан IPv4-адрес.
- Бесконечный цикл перерисовки интерфейса, вызванный нестабильной ссылкой на пустой массив по умолчанию в хуках загрузки данных.
- Сообщение об ошибке при регистрации не отличало сетевые сбои от неверных данных — теперь показывается фактическая причина ошибки.
- Кнопка «назад» в браузере при открытой панели настроек закрывала не только панель, но и уводила с сайта целиком — теперь корректно закрывает только панель, оставаясь на странице.
- Аварийное завершение работы приложения для ранее сохранённых сессий, в которых отсутствовали новые поля профиля, — добавлены значения по умолчанию.

### v0.1.0 «Dev-профиль» — 2026-06-23 – 2026-07-12

Исходная версия: профиль в стиле Steam-сообщества с живой GitHub/Steam-статистикой, бейджами, активностью, настраиваемым фоном — без бэкенда, все данные через публичные API GitHub/Steam и локальный демо-профиль.

---

## Установка и запуск локально

### 1. Требования
- Node.js 20+
- PostgreSQL 17 (локально)

### 2. PostgreSQL

Если ещё не установлен — в **elevated PowerShell** (правой кнопкой → «Запуск от имени администратора»):

```powershell
winget install --id PostgreSQL.PostgreSQL.17 --source winget
```

Установщик попросит задать пароль для пользователя `postgres` — он понадобится в `DATABASE_URL` на следующем шаге.

### 3. Сервер (`Сервер\`)

```bash
cd Сервер
npm install

# Скопировать .env.example → .env и заполнить:
#   DATABASE_URL — с паролем, который задан при установке PostgreSQL
#   JWT_SECRET   — любая длинная случайная строка
cp .env.example .env

# Применить миграции и создать БД (если её ещё нет) — заодно
# автоматически прогонит сид (15 упражнений + боты для лидерборда)
npx prisma migrate dev

# Запуск в dev-режиме (порт 4000, с автоперезапуском)
npm run dev
```

Проверить, что сервер жив: `curl http://127.0.0.1:4000/api/health` → `{"ok":true}`.

Другие полезные команды:
```bash
npm run db:seed      # прогнать сид повторно (безопасно, идемпотентно)
npm run build        # собрать в dist/
npm start             # запустить собранную версию
```

### 4. Клиент (`devprofile\`)

```bash
cd devprofile
npm install

# В .env должны быть (создать при отсутствии):
#   VITE_API_BASE_URL=http://127.0.0.1:4000/api
#   VITE_GITHUB_TOKEN=...      — свой GitHub personal access token (для Dev-вкладки)
#   VITE_STEAM_API_KEY=...     — свой Steam Web API ключ (для Dev-вкладки)

npm run dev
```

Откроется на `http://127.0.0.1:5173` (или следующем свободном порту, если 5173 занят).

### 5. Проверка

1. Открыть клиент в браузере → страница входа/регистрации.
2. Зарегистрировать аккаунт.
3. На вкладке **Fitness** добавить замер/тренировку — должны сохраниться и остаться после обновления страницы (F5).
4. В **Настройках** — указать GitHub/Steam, поменять пароль.
